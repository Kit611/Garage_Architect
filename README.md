Garage Architect

Консольная игра на Python про автомобили и тюнинг. Игрок покупает машины и детали, устанавливает детали для прироста мощности, ремонтирует и повреждает машины. Прогресс сохраняется в базе данных SQLite.

Возможности
Новая игра и загрузка сохранённой по имени игрока (регистр не важен, в том числе для кириллицы).
Автосалон: покупка автомобилей.
Магазин деталей: покупка деталей, каждая даёт прибавку к мощности.
Гараж: установка и снятие деталей, ремонт (платный), просмотр характеристик, повреждение автомобиля.
Можно иметь несколько машин и деталей с одинаковым названием.
Состояние игры сохраняется после каждого значимого действия.
Запуск

Требуется Python 3.8+. Сторонние библиотеки не нужны (используется встроенный sqlite3).

python main.py

При первом запуске файл базы DataBase/game.db и все таблицы создаются автоматически.

Структура проекта
garage_architect/
├── main.py              # точка входа: запускает Game().run()
├── game.py              # класс Game: меню, игровой цикл, сохранение и загрузка
├── DataBase/
│   ├── database.py      # работа с SQLite: схема, save_*, load_*, update_*, delete_*
│   ├── drop_tb.py       # служебный скрипт: удаляет все таблицы (сброс данных)
│   └── game.db          # файл базы данных
└── Models/
    ├── Player/player.py    # Player: деньги, машины, купленные детали, действия игрока
    ├── Car/car.py          # Car: характеристики, ремонт, повреждение, установка деталей
    ├── Parts/part.py       # Part: название, цена, прибавка к мощности, признак установки
    ├── ShopCar/CarShop.py  # CarShop: каталог автомобилей
    └── ShopPart/PartShop.py# ShopPart: каталог деталей
База данных

Таблицы SQLite:

Таблица	Назначение
player	игроки (уникальное имя, баланс)
cars	автомобили игроков (название, мощность, вес, состояние, цена)
parts	купленные детали (название, цена, прибавка)
player_parts	какие детали принадлежат игроку
car_parts	какие детали установлены на какой машине

Деталь остаётся собственностью игрока и после установки: установка отражается записью в car_parts. Мощность машины в БД хранится базовой, при загрузке она пересчитывается с учётом установленных деталей.

Как устроено сохранение
Покупки, установка и снятие деталей записываются в БД сразу.
Баланс и состояние машин обновляются в save_game() после каждого действия и при выходе из игры.
Ошибки БД (нарушение ограничений) перехватываются, программа продолжает работу.
Сброс данных
python DataBase/drop_tb.py

Удаляет все таблицы; при следующем запуске игры они будут созданы заново.
